# الزامات امنیتی

وضعیت سند: پیش‌نویس فاز ۱الف

تاریخ: 1405/09/05

این سند الزام است. در فاز ۰ کدی وجود ندارد و هیچ‌کدام از تست‌های زیر اجرا نشده‌اند. «چطور تست می‌شود» معیار پذیرش پیاده‌سازی بعدی است.

<a id="sec-001"></a>
## SEC-001: بدون رمز اینستاگرام

هیچ فرم، API، یا فیلد دیتابیسی برای رمز اینستاگرام وجود ندارد. اتصال فقط با OAuth رسمی Meta است.

چرا: API رسمی با توکن OAuth کار می‌کند و گرفتن رمز عبور خلاف اصل غیرقابل‌مذاکره‌ی محصول است.

چطور تست می‌شود: طرح دیتابیس، قرارداد API، و فرم‌های UI برای نبود فیلد رمز اینستاگرام بازبینی می‌شوند. جستجوی مخزن نباید محل ذخیره‌ی رمز اینستاگرام را نشان دهد. یک تست اتصال باید فقط مسیر OAuth را داشته باشد.

<a id="sec-002"></a>
## SEC-002: رمزنگاری توکن‌ها

`access token` (long-lived) و هر توکن دیگری که Meta صادر کند در حالت ذخیره با رمزنگاری متقارن قوی (مثلاً AES-256-GCM) رمز می‌شوند. در Instagram API with Instagram Login، refresh token جداگانه وجود ندارد. کلید جدا از دیتابیس نگهداری می‌شود. توکن هرگز در لاگ، پاسخ API، یا فرانت‌اند ظاهر نمی‌شود. کلید قابل چرخش است. منبع: [توکن‌ها](03-instagram-api-constraints.md#s12).

چرا: نشت دیتابیس یا لاگ نباید به‌تنهایی امکان استفاده‌ی توکن Meta را بدهد.

چطور تست می‌شود: مقدار ذخیره‌شده در دیتابیس با توکن خام فرق دارد. تست لاگ و پاسخ API وجود توکن خام را رد می‌کند. تست چرخش کلید، خواندن رکورد قدیمی با کلید جدید را طبق طرح کلید نشان می‌دهد. محل کلید (env یا KMS) تا ADR-011 باز است و این بند آن ADR را Accepted نمی‌کند.

<a id="sec-003"></a>
## SEC-003: تمدید توکن

توکن short-lived با `ig_exchange_token` به توکن long-lived شصت‌روزه تبدیل می‌شود. refresh token جداگانه وجود ندارد. خود همان توکن long-lived با `ig_refresh_token` تمدید می‌شود، به این شرط که دست‌کم ۲۴ ساعت از صدورش گذشته و منقضی نشده باشد. توکن منقضی تمدید نمی‌شود. job زمان‌بندی‌شده لازم است. قبل از انقضا به کاربر هشدار داده می‌شود.

چرا: قطع توکن، اتوماسیون و Inbox را بدون اعلام متوقف می‌کند و توکن منقضی قابل احیا نیست.

چطور تست می‌شود: job در پنجره‌ی مجاز تمدید را صدا می‌زند. قبل از ۲۴ ساعت تمدید نمی‌زند. توکن منقضی را تمدید نمی‌کند و وضعیت اتصال را ناموفق نشان می‌دهد. هشدار قبل از انقضا در تست زمان‌بندی دیده می‌شود. منبع: [توکن‌ها](03-instagram-api-constraints.md#s12).

<a id="sec-004"></a>
## SEC-004: امضای webhook

هدر `X-Hub-Signature-256` با HMAC-SHA256 و app secret روی body خام بررسی می‌شود. مقایسه constant-time است. درخواست نامعتبر رد و لاگ می‌شود. verify token مرحله‌ی subscribe از env خوانده می‌شود.

چرا: بدون بررسی امضا، هر تماس‌گیرنده‌ای می‌تواند رویداد جعلی وارد صف کند.

چطور تست می‌شود: body خام با امضای درست پذیرفته می‌شود. امضای اشتباه، body تغییرکرده، و هدر غایب رد می‌شوند. تست مقایسه نباید به برابری طول یا پیشوند تکیه کند. verify token از env می‌آید و در مخزن مقدار واقعی ندارد.

<a id="sec-005"></a>
## SEC-005: Idempotency

رویداد تکراری webhook با همان `mid` یا comment id فقط یک‌بار پردازش می‌شود. پاسخ `200` سریع برمی‌گردد و پردازش در صف انجام می‌شود.

چرا: Meta رویداد را دوباره می‌فرستد. پردازش دوباره، پیام تکراری می‌سازد. پردازش طولانی داخل درخواست، timeout و تکرار بیشتر می‌سازد.

چطور تست می‌شود: دو تحویل با شناسه‌ی یکسان فقط یک اثر دارند. پاسخ `200` قبل از اتمام کار صف ثبت می‌شود. شناسه‌ی تازه یک‌بار پردازش می‌شود.

<a id="sec-006"></a>
## SEC-006: Data Deletion Callback

endpoint روی HTTPS است، `signed_request` را بررسی می‌کند، حذف داده را آغاز می‌کند، و این JSON را برمی‌گرداند:

```json
{ "url": "...", "confirmation_code": "..." }
```

صفحه‌ی وضعیت حذف هم لازم است.

چرا: ثبت اپ Business Login این callback را می‌خواهد و کاربر باید بتواند وضعیت حذف را ببیند.

چطور تست می‌شود: `signed_request` نامعتبر رد می‌شود. درخواست معتبر کد تأیید و URL وضعیت برمی‌گرداند. صفحه‌ی وضعیت همان کد را نشان می‌دهد. داده‌ی مشمول حذف، پس از job دیگر در دسترس نیست. منبع: [حذف داده](03-instagram-api-constraints.md#s14).

<a id="sec-007"></a>
## SEC-007: Deauthorize Callback

با دریافت callback، اتصال غیرفعال می‌شود، توکن حذف می‌شود، و اتوماسیون‌ها متوقف می‌شوند. جزئیات payload در اسناد Instagram **تأییدنشده** است و هنگام پیاده‌سازی باید بازبینی شود.

چرا: بعد از قطع مجوز توسط کاربر، نگه‌داشتن توکن و ادامه‌ی اتوماسیون خلاف انتظار قطع دسترسی است.

چطور تست می‌شود: پس از callback معتبر، وضعیت اتصال غیرفعال است، توکن ذخیره نیست، و اتوماسیون آن اتصال اجرا نمی‌شود. تا وقتی جزئیات payload تأیید شود، تست قرارداد ورودی ناقص می‌ماند.

<a id="sec-008"></a>
## SEC-008: RBAC

نقش‌ها حداقل این‌ها هستند: Super Admin (پلتفرم)، Owner، Admin، Agent، و Viewer (Workspace). کنترل دسترسی سمت سرور روی هر endpoint انجام می‌شود، نه فقط با مخفی کردن دکمه.

چرا: مخفی کردن دکمه دسترسی واقعی را عوض نمی‌کند.

چطور تست می‌شود: هر endpoint برای نقش مجاز و نقش غیرمجاز تست می‌شود. کاربر Viewer عملیات نوشتن را از API هم نمی‌تواند انجام دهد، حتی اگر دکمه در UI نباشد. Super Admin نقش Workspace نیست.

<a id="sec-009"></a>
## SEC-009: جداسازی tenant

هر رکورد به `workspace_id` تعلق دارد. همه‌ی کوئری‌ها با فیلتر tenant اجرا می‌شوند. تست خودکار نشت داده بین tenantها الزامی است. دسترسی Super Admin جدا و لاگ‌شده است.

چرا: در SaaS چندمستأجره، دیدن داده‌ی کسب‌وکار دیگر نقض مرز محصول است.

چطور تست می‌شود: دو Workspace ساخته می‌شوند. شناسه‌ی رکورد tenant اول با نشست tenant دوم خوانده، ویرایش، یا حذف نمی‌شود. تست Super Admin دسترسی را جداگانه و همراه رکورد Audit Log نشان می‌دهد. این بند بین دیتابیس مشترک، schema جدا، یا دیتابیس جدا تصمیم نمی‌گیرد؛ آن تصمیم ADR-002 است.

<a id="sec-010"></a>
## SEC-010: Audit Log

عملیات حساس ثبت می‌شوند: ورود، اتصال و قطع پیج، تغییر اتوماسیون، تغییر نقش، پرداخت، دسترسی Super Admin، و حذف داده. هر رکورد زمان، کاربر، IP، و tenant دارد. لاگ‌ها غیرقابل‌ویرایش‌اند.

چرا: بدون سابقه‌ی ثابت، حادثه و اقدام مدیر قابل پیگیری نیست.

چطور تست می‌شود: هر عملیات فهرست بالا یک رکورد با همان چهار فیلد می‌سازد. مسیر ویرایش یا حذف لاگ برای نقش‌های محصول وجود ندارد.

<a id="sec-011"></a>
## SEC-011: Secrets

همه‌ی secretها فقط در env یا secret manager هستند. `.env` هرگز commit نمی‌شود. `.env.example` فقط placeholder دارد.

چرا: secret داخل مخزن قابل پس‌گرفتن قطعی نیست و در تاریخچه‌ی Git می‌ماند.

چطور تست می‌شود: `.gitignore` فایل `.env` را نادیده می‌گیرد و `.env.example` را نه. مقدارهای `.env.example` خالی یا placeholder بدون رمز واقعی‌اند. جستجوی مخزن کلید خصوصی، توکن، یا رمز واقعی را نشان نمی‌دهد.

<a id="sec-012"></a>
## SEC-012: احراز هویت پنل

OTP و ورود محدودیت نرخ دارند. OTP انقضای کوتاه دارد. بعد از تلاش‌های ناموفق، قفل موقت فعال می‌شود. کوکی نشست `HttpOnly`، `Secure`، و `SameSite` است. محافظت CSRF وجود دارد.

چرا: OTP و نشست بدون این کنترل‌ها قابل حدس، بازپخش، یا استفاده‌ی متقابل‌اند.

چطور تست می‌شود: درخواست اضافه بر سقف نرخ رد می‌شود. OTP منقضی قبول نمی‌شود. تلاش ناموفق پیاپی قفل موقت می‌سازد. ویژگی کوکی در پاسخ ورود بررسی می‌شود. درخواست تغییر حالت بدون نشان CSRF رد می‌شود. خود روش ورود (OTP، ایمیل و رمز، یا هر دو) تا ADR-009 باز است.

<a id="sec-013"></a>
## SEC-013: OWASP پایه

ورودی‌ها اعتبارسنجی می‌شوند. پیش‌نمایش پیام در برابر XSS محافظت می‌شود. کوئری‌ها در برابر SQL Injection محافظت می‌شوند. لینک و رسانه در برابر SSRF محافظت می‌شوند. نوع و حجم آپلود محدود است: عکس 8MB، ویدیو و صدا 25MB.

چرا: پیش‌نمایش پیام، لینک رسانه، و فایل آپلودی ورودی غیرقابل‌اعتمادند.

چطور تست می‌شود: ورودی خارج از طرح رد می‌شود. متن پیام حاوی نشانه‌گذاری در پیش‌نمایش اجرا نمی‌شود. تست تزریق SQL به کوئری پارامترشده اثر ندارد. آدرس داخلی یا غیرمجاز برای رسانه رد می‌شود. فایل بزرگ‌تر از سقف و نوع غیرمجاز قبول نمی‌شود.

<a id="sec-014"></a>
## SEC-014: حریم خصوصی

داده کمینه جمع می‌شود. سیاست نگهداری داده وجود دارد. اگر قانون افشای خودکار بودن گفتگو را بخواهد، افشا انجام می‌شود.

چرا: سیاست Meta افشای بات را در صورت الزام قانونی لازم دانسته، و نگهداری بیش از نیاز خلاف کمینه‌سازی است.

چطور تست می‌شود: فهرست داده‌ی ذخیره‌شده با فهرست نیاز محصول مقایسه می‌شود. job نگهداری، داده‌ی مشمول انقضا را حذف یا ناشناس می‌کند. جایی که افشا لازم باشد، متن خودکار بودن در گفتگو قابل مشاهده است.

<a id="sec-015"></a>
## SEC-015: انطباق با سیاست Meta

قابلیت Cold DM، پیام انبوه، اسکرپ، فالو یا آنفالو، و فالو اجباری ساخته نمی‌شود. `HUMAN_AGENT` فقط برای پاسخ انسانی استفاده می‌شود.

چرا: این موارد در ردیف `F-NEVER` با وضعیت `not-allowed` آمده‌اند یا در سند API پشتیبانی نمی‌شوند.

چطور تست می‌شود: فهرست قابلیت محصول ردیف `Never` ندارد. تست ارسال، گیرنده‌ای را که در پنجره‌ی مجاز نیست هدف نمی‌گیرد. مسیر `HUMAN_AGENT` فقط از اقدام عامل انسانی فعال می‌شود، نه از کمپین تبلیغاتی. جزئیات محدودیت در [سند API](03-instagram-api-constraints.md#s9) است.
