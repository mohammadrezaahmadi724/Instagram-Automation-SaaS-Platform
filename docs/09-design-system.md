# سیستم طراحی

وضعیت سند: پیش‌نویس فاز ۱ب

تاریخ: 1405/09/04

این سند منبع حقیقت ظاهر دایرکتورا است. توکن‌های رنگ در `packages/ui/src/tokens.css` به CSS variables تبدیل می‌شوند. مقدارهای رنگ پالت لوگوی دایرکتورا هستند و عیناً ثبت شده‌اند. همه‌ی جفت‌های متنی جدول بخش ۳ حد AA را پاس می‌کنند.

هویت بصری: آرام، دقیق و premium. پالت لوگوی دایرکتورا است: `blue`، `cyan`، `ink`، `orange` و `amber`. ماژنتا، صورتی، و گرادیان نارنجی-صورتی رابط اینستاگرام ممنوع است. کپی Directam ممنوع است.

<a id="s1"></a>
## 1. اصول طراحی

### 1. آرام و متمرکز

فضای سفید کافی، یک اقدام اصلی در هر صفحه، و پرهیز از شلوغی.

- درست: صفحه‌ی لیست فقط یک دکمه‌ی «ساخت اتوماسیون» به‌عنوان اقدام اصلی دارد.
- غلط: همان صفحه هم‌زمان پنج دکمه‌ی رنگی هم‌وزن نشان می‌دهد.

### 2. شفافیت در برابر محدودیت

محدودیت‌های Meta همیشه در لحظه‌ی تصمیم دیده شوند، مثل شمارنده‌ی ۲۴ ساعت و «یک پیام خصوصی برای هر کامنت».

- درست: کنار Private Reply نوشته شده «فقط یک پیام خصوصی برای هر کامنت، تا ۷ روز».
- غلط: کاربر بعد از ذخیره می‌فهمد که پیام دوم برای همان کامنت ارسال نمی‌شود.

### 3. واقعی، نه نمایشی

هر عنصر کار واقعی انجام می‌دهد. قابلیت آماده‌نشده نمایش داده نمی‌شود، یا غیرفعال و با برچسب «به‌زودی» می‌آید.

- درست: دکمه‌ی «گزارش پیشرفته» غیرفعال است و برچسب «به‌زودی» دارد، چون backend ندارد.
- غلط: دکمه‌ای که `onClick` خالی دارد یا به `href="#"` می‌رود.

### 4. بازخورد فوری

هر اقدام در کمتر از ۱۰۰ میلی‌ثانیه پاسخ بصری می‌گیرد، مثل pressed، loading یا optimistic.

- درست: دکمه‌ی ذخیره همان لحظه حالت pressed و سپس spinner می‌گیرد، بدون تغییر عرض.
- غلط: صفحه تا جواب سرور هیچ تغییری نمی‌کند.

### 5. فارسی‌محور

RTL واقعی، تایپوگرافی فارسی باکیفیت، اعداد فارسی و تقویم شمسی.

- درست: «۱۲٬۵۰۰٬۰۰۰ تومان» و «۵ آذر ۱۴۰۵».
- غلط: `12500000 IRR` و `2026-11-25` در متن رابط.

### 6. دسترس‌پذیر برای همه

WCAG 2.2 AA حداقل است، نه هدف.

- درست: حلقه‌ی focus با کیبورد دیده می‌شود و کنتراست متن عادی حداقل ۴٫۵ است. جفت‌های جدول بخش ۳ این حد را پاس می‌کنند. مرز فیلد با `--border-input` حد غیرمتنی ۳ را پاس می‌کند.
- غلط: حذف حلقه‌ی focus برای ظاهر تمیزتر.

### 7. هویت مستقل

هیچ شباهت عمدی به Directam یا UI رسمی اینستاگرام وجود ندارد. از رنگ ماژنتا یا گرادیان صورتی و نارنجی اینستاگرام استفاده نمی‌شود.

- درست: قاب پیش‌نمایش گوشی عمومی و اختصاصی ماست و حباب‌ها از توکن‌های `surface` و `primary-subtle` می‌آیند.
- غلط: کپی چیدمان، آیکون یا گرادیان رابط اینستاگرام.

### گرادیان‌ها

توکن مستقل‌اند:

- `--gradient-brand: linear-gradient(135deg, blue-600, cyan-500)`. تزئینی است: نشانه‌ی برند، نوار hero، حاشیه‌ی کارت ویژه و آیکون. متن روی آن ممنوع است، چون سفید روی `cyan-500` فقط ۲٫۳۵ کنتراست دارد.
- `--gradient-accent: linear-gradient(135deg, orange-500, amber-500)`. برای CTA ویژه و نشان «جدید». متن روی آن فقط `ink-900` است (≥ ۶٫۴۸). متن سفید روی نارنجی ممنوع است (۲٫۶۱).
- در RTL، جهت گرادیان آینه نمی‌شود، چون معنای جهتی ندارد.

### Chart palette

`chart-1=blue-600`، `chart-2=cyan-500`، `chart-3=orange-500`، `chart-4=green-500`، `chart-5=#7C5CE0` (بنفش؛ فقط برای نمودار)، `chart-6=amber-500`.

هر سری علاوه بر رنگ، نشانه‌ی دیگری هم دارد: الگو، برچسب یا شکل نقطه. معنا فقط با رنگ منتقل نمی‌شود. `chart-5` بنفش نمودار است، نه رنگ برند. در سطح بزرگ به‌عنوان پس‌زمینه یا دکمه‌ی اصلی استفاده نمی‌شود.

### فرمول کنتراست

نسبت کنتراست WCAG 2.2:

1. هر کانال sRGB را بر ۲۵۵ تقسیم کن.
2. اگر مقدار ≤ ۰٫۰۴۰۴۵ باشد، خطی‌شده برابر است با تقسیم بر ۱۲٫۹۲. وگرنه `((مقدار + ۰٫۰۵۵) / ۱٫۰۵۵) ^ ۲٫۴`.
3. درخشندگی نسبی: `L = 0.2126 R + 0.7152 G + 0.0722 B`.
4. نسبت: `(L روشن‌تر + 0.05) / (L تیره‌تر + 0.05)`.

عددها با همین فرمول و بدون پکیج حساب شده‌اند و تا دو رقم اعشار گرد شده‌اند. حد قبولی متن عادی ۴٫۵ است. حد متن بزرگ و عنصر غیرمتنی ۳ است.

## 4. تایپوگرافی

- فونت: `Vazirmatn` (variable، SIL OFL 1.1)، وزن‌های ۴۰۰، ۵۰۰، ۶۰۰، ۷۰۰ و ۸۰۰. fallback: `system-ui, sans-serif`.
- فونت mono: `JetBrains Mono` برای شناسه، کد، OTP و URL.
- هر دو self-host می‌شوند. CDN ممنوع است. فایل مجوز در 01b کنار فونت قرار می‌گیرد.

| توکن | اندازه / line-height / وزن |
| --- | --- |
| `text-xs` | 12/20/400 |
| `text-sm` | 14/24/400 |
| `text-base` | 16/28/400 |
| `text-lg` | 18/30/500 |
| `text-xl` | 20/32/600 |
| `text-2xl` | 24/36/700 |
| `text-3xl` | 30/42/700 |
| `text-4xl` | 36/50/800 |
| `display` | 48/64/800 |

اندازه‌ها به پیکسل‌اند. line-height متن فارسی حداقل ۱٫۶ است. `text-base` برابر ۱۶/۲۸ است، یعنی ۱٫۷۵. letter-spacing برای فارسی صفر است و هرگز منفی نمی‌شود. حداکثر عرض پاراگراف ۷۰ کاراکتر است. عدد در جدول‌ها `font-variant-numeric: tabular-nums` دارد.

### اعداد

همه‌ی اعداد نمایشی با `Intl.NumberFormat('fa-IR')` فارسی می‌شوند و جداکننده‌ی هزارگان دارند.

استثناها، همه LTR و داخل `<bdi>` یا `dir="ltr"`: شماره تلفن در حالت ورود، کد OTP، شناسه‌های فنی، و URL.

ورودی کاربر با رقم فارسی و انگلیسی هر دو پذیرفته و قبل از ذخیره نرمال می‌شود.

### پول

نمایش: «۱۲٬۵۰۰٬۰۰۰ تومان». در دیتابیس عدد صحیح است، نه float. پیشنهاد ذخیره، ریال صحیح است و در [طراحی دیتابیس](10-database.md) با علامت نیازمند تأیید مالک ثبت شده است. `formatToman` مبلغ منفی را نمی‌پذیرد.

### تاریخ

در UI شمسی است: «۵ آذر ۱۴۰۵» یا «۱۴۰۵/۰۹/۰۵». زمان نسبی هم هست: «۳ دقیقه پیش». منطقه‌ی زمانی نمایش `Asia/Tehran` است. ذخیره‌سازی `timestamptz` به UTC است (ADR-002).

حالت روشن، لایه‌ای و نرم، با رنگ پایه‌ی `ink-900`:

| توکن | مقدار |
| --- | --- |
| `xs` | `0 1px 2px rgb(23 26 34 / 0.05)` |
| `sm` | `0 1px 3px rgb(23 26 34 / 0.08), 0 1px 2px rgb(23 26 34 / 0.04)` |
| `md` | `0 4px 12px rgb(23 26 34 / 0.08), 0 2px 4px rgb(23 26 34 / 0.04)` |
| `lg` | `0 12px 32px rgb(23 26 34 / 0.12), 0 4px 8px rgb(23 26 34 / 0.04)` |
| `focus` | `0 0 0 3px` با رنگ `--ring` و شفافیت ۳۵٪ |

در حالت تیره سایه‌ها کم‌رنگ می‌شوند و عمق با `--border` و `--surface-raised` ساخته می‌شود.

### Z-index

| توکن | مقدار |
| --- | --- |
| `base` | 0 |
| `dropdown` | 1000 |
| `sticky` | 1100 |
| `overlay` | 1200 |
| `modal` | 1300 |
| `popover` | 1400 |
| `toast` | 1500 |
| `tooltip` | 1600 |

### Breakpoint

Mobile-first: `sm=640`، `md=768`، `lg=1024`، `xl=1280`، `2xl=1536`. واحد پیکسل است.

### Layout

سایدبار ۲۷۲px و در حالت جمع‌شده ۷۶px. هدر ۶۴px. حداکثر عرض محتوا ۱۲۸۰px. padding صفحه ۱۶px در موبایل و ۳۲px از `lg` به بالا.

<a id="s6"></a>
## 6. Motion

| توکن | مقدار |
| --- | --- |
| `instant` | 0 |
| `fast` | 120ms |
| `base` | 180ms |
| `slow` | 240ms |
| `slower` | 360ms |

easing:

- `standard`: `cubic-bezier(0.2, 0, 0, 1)`
- `emphasized`: `cubic-bezier(0.3, 0, 0, 1)`
- `exit`: `cubic-bezier(0.4, 0, 1, 1)`

فقط `transform` و `opacity` انیمیت می‌شوند. modal و sheet با slide و fade در `slow` باز می‌شوند. toast از پایین وارد می‌شود. skeleton پالس ملایم دارد. با `prefers-reduced-motion` همه‌ی حرکت‌ها به fade کوتاه یا هیچ تبدیل می‌شوند. هیچ انیمیشن تزئینی بیشتر از ۴۰۰ms نیست.

<a id="s7"></a>
## 7. قواعد RTL

- `<html lang="fa" dir="rtl">` در کل اپ.
- فقط CSS logical properties: `ms-*`، `me-*`، `ps-*`، `pe-*`، `start-*`، `end-*`، `text-start`. `ml-*`، `mr-*`، `pl-*`، `pr-*`، `left-*`، `right-*`، `text-left` و `text-right` ممنوع‌اند، مگر با توضیح در گزارش همان تسک.
- آیکون جهت‌دار (فلش، chevron، back) با `rtl:-scale-x-100` آینه می‌شود. play، چک و ساعت آینه نمی‌شوند.
- سایدبار سمت راست است. جداکننده‌ی breadcrumb `‹` است. progress و stepper از راست به چپ پر می‌شوند.
- متن مختلط با `<bdi>` ایزوله می‌شود. فیلد ایمیل، URL، شماره و کد `dir="ltr"` دارند و label راست‌چین می‌ماند.
- نمودار: محور زمان از راست به چپ است و برچسب‌ها عدد فارسی دارند.

<a id="s8"></a>
## 8. فهرست کامپوننت‌ها

برای هر مورد، stateهای `default`، `hover`، `focus-visible`، `active`، `disabled`، `loading` و `error` اگر به آن کنترل مربوط باشند پیاده می‌شوند. جایی که state معنی ندارد، همان‌جا نوشته شده است.

### Button

هدف: اقدام اصلی یا فرعی. variant: `primary`، `secondary`، `ghost`، `outline`، `destructive`، `link`. size: `sm`، `md`، `lg`، `icon`. در `loading` spinner می‌آید و عرض دکمه ثابت می‌ماند. `disabled` اقدام را نمی‌فرستد. error روی خود دکمه نیست و در فیلد یا toast می‌آید. کیبورد: `Enter` و `Space`. RTL: آیکون جهت‌دار داخل دکمه آینه می‌شود. موبایل: ارتفاع لمسی حداقل ۴۴px.

### IconButton

هدف: اقدام فقط-آیکون با `aria-label` اجباری. variant و state مانند Button. size فقط `icon`. tooltip نام اقدام را می‌گوید. کیبورد مانند Button. بدون label ممنوع است.

### Input

هدف: متن یک‌خطی. size: `sm`، `md`، `lg`. stateها شامل error با متن زیر فیلد. مرز فیلد از `--border-input` است، نه از `--border-strong`. کیبورد: Tab به ترتیب RTL. `dir="ltr"` فقط برای ایمیل، URL، شناسه و شماره. label جدا از placeholder است.

### Textarea

هدف: متن چندخطی، از جمله پیام دایرکت. شمارنده‌ی بایت برای سقف ۱۰۰۰ بایت Send API. variant ندارد. size: `md`. error وقتی از سقف بگذرد. کیبورد: Enter خط جدید می‌سازد و ارسال با میانبر جدا است، نه با Enter تنها. موبایل: حداقل چهار خط دیده شود.

### Select

هدف: انتخاب از فهرست بسته. size: `sm`، `md`. stateها شامل error. مرز فیلد از `--border-input` است. کیبورد: پیکان، Enter، Esc، نویسه‌ی اول برای پرش. RTL: چک انتخاب در سمت شروع. موبایل: فهرست به‌صورت sheet اگر گزینه‌ها زیاد باشند.

### Combobox

هدف: جستجو داخل گزینه‌ها، مثل انتخاب پست. stateها شامل loading نتایج و empty «نتیجه‌ای نیست». کیبورد: مانند Select به‌علاوه‌ی تایپ. RTL: متن گزینه راست‌چین و شناسه‌ی پست LTR.

### Checkbox

هدف: انتخاب چندتایی. size: ۲۰px با هدف لمسی ۴۴px. stateها شامل `indeterminate`. مرز مربع از `--border-input` است. error برای گروه اجباری. کیبورد: Space.toggle. RTL: مربع در سمت راست برچسب.

### Radio

هدف: یک گزینه از چند گزینه. size و کیبورد مانند Checkbox. داخل گروه یکی انتخاب می‌شود. error روی گروه است.

### Switch

هدف: روشن/خاموش فوری، مثل فعال بودن اتوماسیون. size: `md`. loading تا پاسخ سرور. کیبورد: Space. RTL: دایره به سمت شروع حرکت می‌کند وقتی روشن است.

### Slider

هدف: مقدار عددی پیوسته، اگر در محصول لازم شد. size: `md`. کیبورد: پیکان با گام. RTL: افزایش به سمت چپ نیست. افزایش به سمتی است که در RTL «بیشتر» خوانده شود و در 01b با تست جهت ثابت می‌شود. error اگر خارج از بازه باشد.

### DatePicker شمسی

هدف: انتخاب تاریخ شمسی. size: `md`. تقویم از راست. امروز و روز انتخاب‌شده مشخص‌اند. کیبورد: پیکان روزها در جهت RTL. ورودی دستی «۱۴۰۵/۰۹/۰۵» هم قبول است. error برای تاریخ نامعتبر.

### OTP Input

هدف: کد یکبارمصرف. شش خانه، LTR، paste کل کد. size: `md`. error برای کد اشتباه، loading هنگام بررسی. کیبورد: رقم بعدی خودکار، Backspace خانه‌ی قبلی. شماره و کد هرگز رقم فارسیِ نمایشیِ جدا از مقدار ورودی نیستند. مقدار داخلی نرمال می‌شود.

### Phone Input

هدف: موبایل با پیش‌شماره‌ی ایران. `dir="ltr"`. size: `md`. error برای شماره‌ی نامعتبر. کیبورد عددی در موبایل.

### Badge

هدف: وضعیت کوتاه، مثل «فعال». variant: `neutral`، `success`، `warning`، `danger`، `info`. size: `sm`. hover و active ندارد. رنگ تنها نشان وضعیت نیست و متن هم هست. اگر کنتراست متن کوچک روی subtle در جدول `❌` است، متن badge با وزن ۶۰۰ و اندازه‌ی حداقل ۱۴px یا همراه آیکون می‌آید تا به متن خیلی ریز تکیه نکند.

### Tag

هدف: برچسب قابل برداشتن، مثل کلمه. size: `sm`، `md`. دکمه‌ی حذف `aria-label` دارد. کیبورد: Backspace روی تگ متمرکز آن را حذف می‌کند.

### Avatar

هدف: تصویر یا حرف اول نام. size: `sm`، `md`، `lg`. تصویر `alt` دارد. اگر تصویر نیاید حرف نشان داده می‌شود. شکل `full`.

### Tooltip

هدف: توضیح کوتاه روی hover و focus. با کیبورد هم باز می‌شود. Esc می‌بندد. روی لمس، با فوکوس یا فشار طولانی. متن ضروری را فقط داخل tooltip نگذارید.

### Kbd

هدف: نمایش میانبر، مثل `Ctrl+K`. LTR. size: `sm`. تعاملی نیست.

### Divider

هدف: جدا کردن بخش. افقی با logical margin. vertical فقط داخل نوار ابزار و در RTL محور منطقی دارد.

### Skeleton

هدف: loading هم‌شکل محتوا. پالس ملایم. با reduced-motion ثابت می‌شود. دکمه‌ی جعلی نیست.

### Spinner

هدف: انتظار کوتاه داخل دکمه یا ناحیه‌ی کوچک. برای بارگذاری صفحه به‌تنهایی استفاده نمی‌شود. `aria-busy` روی والد.

### App Shell

هدف: قاب `header`، `nav`، `main`، `aside`. loading کل اپ یک skeleton پوسته است، نه spinner تمام‌صفحه. کیبورد: لینک «پرش به محتوا» اول tab است.

### Sidebar

هدف: ناوبری اصلی در سمت راست. گروه‌بندی منو، آیتم فعال، شمارنده، جمع شدن به ۷۶px. در موبایل Sheet از راست. کیبورد: پیکان بین آیتم‌ها. آیتم فعال هم با رنگ و هم با نشانه‌ی غیررنگی مشخص است.

### Header

هدف: عنوان صفحه، جستجوی سراسری با `Ctrl+K`، دکمه‌ی «ایجاد سریع»، اعلان‌ها، انتخاب‌گر Workspace، انتخاب‌گر حساب اینستاگرام، منوی کاربر، تغییر تم. ارتفاع ۶۴px. در موبایل جستجو آیکون است و «ایجاد سریع» به نوار پایین می‌رود اگر جا نباشد.

### Page Header

هدف: عنوان، توضیح یک‌خطی، و یک اقدام اصلی. size ثابت. در موبایل اقدام اصلی به نوار پایین چسبان منتقل می‌شود.

### Breadcrumb

هدف: مسیر صفحه. جداکننده `‹`. کیبورد: لینک‌ها در ترتیب RTL. آخرین بخش لینک نیست.

### Tabs

هدف: تعویض نمای هم‌سطح. کیبورد: پیکان در جهت RTL، Home و End. panel با `tabindex` مدیریت می‌شود. در موبایل اگر جا نشد اسکرول افقی داخل خود تب‌ها، نه کل صفحه.

### Segmented Control

هدف: دو تا چهار گزینه‌ی هم‌ارز، مثل بازه‌ی نمودار. کیبورد مانند Tabs. انتخاب فقط با رنگ نیست.

### Card

هدف: سطح محتوا. variant: `stat`، `list`، `action`. radius `lg`. سایه‌ی `sm` در روشن. در تیره مرز به‌جای سایه‌ی سنگین. کلیک کل کارت فقط اگر یک مقصد داشته باشد و هنوز دکمه‌ی داخلی جدا قابل‌فوکوس باشد.

### Section

هدف: گروه با عنوان `text-lg`. فاصله‌ی `8` از بخش بعدی. اقدام بخش در سمت شروع (راست در RTL).

### Data Table

هدف: داده‌ی جدولی. مرتب‌سازی، فیلتر، جستجو، صفحه‌بندی، انتخاب سطر، bulk action، ستون قابل‌پنهان، empty و loading. کیبورد: روی سطر و چک‌باکس. عددها tabular و فارسی. در موبایل هر سطر یک کارت می‌شود و اسکرول افقی صفحه ممنوع است. error بارگذاری، Error State داخل جدول است.

### Stat Card

هدف: یک شاخص با روند. روند علاوه بر رنگ، فلش و متن «بیشتر» یا «کمتر» دارد. loading یک skeleton عدد است.

### Chart

هدف: `line`، `area`، `bar`، `donut`. tooltip فارسی، legend قابل‌کلیک، محور زمان از راست به چپ، اعداد فارسی. هر سری الگو یا شکل جدا دارد. رنگ‌ها `chart-1..6`. empty وقتی داده نیست.

### Timeline

هدف: فعالیت اخیر از بالا به پایین. در RTL خط زمان سمت راست متن است. زمان نسبی فارسی.

### Description List

هدف: جفت برچسب و مقدار، مثل جزئیات اتصال. مقدارهای فنی LTR. در موبایل برچسب بالای مقدار است.

### Toast

هدف: بازخورد گذرا. variant: `success`، `error`، `warning`، `info`، و `undo`. از پایین وارد می‌شود. `aria-live="polite"` و برای error `assertive`. کیبورد: فوکوس به اقدام undo اگر باشد. `sonner` فقط پوسته‌ی رفتار است و ظاهر از توکن‌های ما می‌آید.

### Alert

هدف: پیام ماندگار داخل صفحه. variant مانند Toast بدون undo. آیکون به‌علاوه‌ی متن. رنگ تنها حامل معنا نیست.

### Banner

هدف: نوار سراسری، از جمله سلامت اتصال و انقضای توکن. قابل بستن فقط اگر اطلاع اختیاری باشد. انقضای توکن بدون اقدام «اتصال دوباره» بسته نمی‌شود.

### Modal و Dialog

هدف: کار متمرکز. radius `xl`. focus trap. Esc می‌بندد. کلیک روی overlay فقط اگر کار مخرب نباشد می‌بندد. دکمه‌ی اصلی در سمت شروع RTL، یعنی سمت راست گروه دکمه‌ها. در موبایل bottom sheet است.

### Confirm Dialog

هدف: عملیات مخرب. برای حذف مهم، کاربر باید نام را تایپ کند. دکمه‌ی تأیید `destructive` است. Enter روی فیلد نام، تا وقتی متن جور نشده، حذف را اجرا نمی‌کند.

### Drawer و Sheet

هدف: پانل کناری. در RTL از راست وارد می‌شود. سایدبار موبایل و پیش‌نمایش موبایل از همین الگو هستند. Esc و focus trap مانند Dialog.

### Popover

هدف: محتوای کوچک لنگرشده به یک دکمه. کیبورد باز و Esc برای بستن. z-index `popover`.

### Progress

هدف: پیشرفت مرحله یا آپلود. از راست به چپ پر می‌شود. درصد فارسی و یک متن همراه دارد.

### Empty State

هدف: اولین استفاده، یا نتیجه‌ی فیلتر خالی. این دو متن متفاوت‌اند. تصویرسازی ساده‌ی اختصاصی یا آیکون، عنوان، توضیح، و CTA واقعی. تصویرسازی Directam یا اینستاگرام ممنوع است.

### Error State

هدف: شکست بارگذاری. چه شد، چرا شد، چه کار کنیم، و شناسه‌ی خطا برای پشتیبانی. اقدام «تلاش دوباره» اگر تکرار معنی دارد.

### No-permission State

هدف: نقش کاربر اجازه ندارد. دکمه مخفی نمی‌شود تا بعداً ۴۰۳ بی‌توضیح بیاید. متن می‌گوید از چه نقشی باید درخواست کرد. API هم باید ۴۰۳ بدهد. مخفی کردن تنها کافی نیست.

### Form Field

هدف: label، توضیح، خطای inline، نشان اجباری. خطا با `aria-describedby` به فیلد وصل است. placeholder جای label نیست.

### Form Section

هدف: گروه فیلدها با عنوان. فاصله‌ی `6` بین فیلدها.

### خلاصه‌ی خطا

هدف: بالای فرم طولانی، فهرست خطاها که هر کدام به فیلدش می‌رود. وقتی بیش از یک خطا هست نشان داده می‌شود.

### هشدار تغییرات ذخیره‌نشده

هدف: قبل از ترک صفحه اگر فرم کثیف است. Dialog با «ماندن» و «ترک بدون ذخیره».

### Stepper Wizard ساخت اتوماسیون

هدف: ساخت اتوماسیون در پنج مرحله.

1. ماشه: دایرکت، کامنت پست/ریل، ریپلای استوری.
2. شرط تطبیق: دقیق، شامل، شروع با، هر پیام. مثال درست و غلط زنده.
3. پاسخ: متن و عکس در MVP.
4. تنظیمات بیشتر: پاسخ عمومی کامنت، و نمایش محدودیت‌ها.
5. بازبینی و فعال‌سازی.

رفتار: ذخیره‌ی پیش‌نویس، برگشت بدون از دست رفتن داده، اعتبارسنجی هر مرحله، نوار پیشرفت RTL. دسکتاپ دوستونی است. موبایل پیش‌نمایش را در Sheet جدا باز می‌کند. کیبورد: دکمه‌ی «بعدی» و «قبلی» در ترتیب منطقی. مرحله‌ی ناتمام قابل پرش با کلیک روی stepper نیست مگر مرحله‌های قبلی معتبر باشند.

### Live Phone Preview

هدف: قاب گوشی عمومی و اختصاصی ما، نه کپی UI اینستاگرام. پیام کاربر و پاسخ خودکار را لحظه‌ای نشان می‌دهد. شمارنده‌ی بایت، هشدار «فقط یک پیام خصوصی برای هر کامنت، تا ۷ روز»، و پنجره‌ی ۲۴ ساعته را نشان می‌دهد. در تم تیره و روشن کار می‌کند. تعاملی برای ارسال واقعی نیست. این پیش‌نمایش است، نه Inbox.

### Inbox

هدف: لیست گفتگو با شمارنده‌ی زمان باقی‌مانده از پنجره‌ی ۲۴ ساعته، thread پیام، و composer. بیرون از پنجره composer غیرفعال است و دلیل را می‌گوید. برچسب «خودکار» و «انسانی» روی پیام هست. در موبایل اول لیست و بعد thread. کیبورد: پیکان بین گفتگوها.

### Connection Health Card

هدف: وضعیت اتصال، زمان انقضای توکن، و آخرین webhook دریافت‌شده. اگر توکن نزدیک انقضا باشد Banner هم می‌آید. اقدام «اتصال دوباره» واقعی است. زمان‌ها شمسی و به وقت `Asia/Tehran` هستند.

### Keyword Chips Input

هدف: چند کلمه‌ی ماشه. Enter یا ویرگول یک chip می‌سازد. chip حذف‌شدنی است. خالی بودن در مرحله‌ی شرط، error است مگر نوع تطبیق «هر پیام» باشد. متن chip با `<bdi>` اگر مخلوط باشد.

## 9. الگوهای صفحه

سایدبار در این قاب‌ها سمت راست است.

### داشبورد

دسکتاپ:

```
+-----------------------------------------------+------------------+
| هدر: عنوان، جستجو، ایجاد سریع، تم             | سایدبار          |
+-----------------------------------------------+  نشان            |
| [آمار] [آمار] [آمار] [آمار]                   |  منو             |
| +---------------------------+ +--------------+|                  |
| | نمودار                    | | فعالیت اخیر  ||                  |
| +---------------------------+ +--------------+|                  |
| چک‌لیست شروع برای کاربر جدید                  |                  |
+-----------------------------------------------+------------------+
```

موبایل: سایدبار بسته است. آمارها زیر هم. نمودار تمام‌عرض. نوار پایین برای ایجاد سریع. چک‌لیست بالای نمودار اگر کاربر تازه باشد.

### لیست اتوماسیون‌ها

دسکتاپ: Page Header با «ساخت اتوماسیون»، سپس فیلتر و جستجو، سپس جدول. موبایل: کارت به‌جای جدول و دکمه‌ی ساخت در نوار پایین.

### ویزارد

دسکتاپ:

```
+---------------------------+------------------+------------------+
| پیش‌نمایش گوشی            | فرم مرحله        | سایدبار          |
| شمارنده‌ی بایت            | stepper از راست  |                  |
| هشدار Private Reply       | اقدام: بعدی      |                  |
+---------------------------+------------------+------------------+
```

موبایل: فرم تمام‌عرض. دکمه‌ی «پیش‌نمایش» Sheet را از پایین باز می‌کند. اقدام بعدی چسبان است.

### Inbox

دسکتاپ: ستون thread، ستون لیست گفتگو، سایدبار. شمارنده‌ی ۲۴ ساعت روی هر ردیف. موبایل: فقط لیست، سپس صفحه‌ی thread. composer اگر پنجره بسته باشد غیرفعال و توضیح‌دار است.

### مخاطبین

دسکتاپ: جدول با جستجو و خروجی. موبایل: کارت. دکمه‌ی خروجی در منوی بیشتر، نه یک ردیف دکمه‌ی شلوغ.

### تنظیمات

دسکتاپ: محتوای بخش در چپِ منطقی، ناوبری بخش‌ها سمت راست. موبایل: اول فهرست بخش‌ها، بعد خود بخش.

### اشتراک و پرداخت

دسکتاپ: کارت پلن فعلی و اقدام پرداخت. قیمت با تومان و رقم فارسی. موبایل: یک کارت تمام‌عرض و دکمه‌ی پرداخت چسبان. تا ADR-007، اگر درگاه وصل نیست دکمه «به‌زودی» و غیرفعال است.

### Onboarding اتصال اینستاگرام

دسکتاپ: توضیح کوتاه، شرط حساب Professional، دکمه‌ی «اتصال رسمی». هیچ فیلد رمز اینستاگرام نیست. موبایل: همان ستون واحد. خطا اگر حساب شخصی باشد، با متن قابل‌فهم.

### ورود و OTP

دسکتاپ: کارت باریک وسط `surface`. موبایل: همان کارت تمام‌عرض با padding ۱۶. شماره‌ی تلفن و OTP هر دو LTR. شش خانه‌ی OTP. تا Accepted شدن ADR-009، این الگو فقط مشخصات بصری است و پیاده‌سازی ورود در فاز ۳ است.

<a id="s10"></a>
## 10. ماتریس حالت‌ها

`loading` همیشه skeleton هم‌شکل محتواست، نه spinner تمام‌صفحه. `empty` اولین استفاده با empty فیلتر فرق دارد.

| الگو | loading | empty | error | success | no-permission |
| --- | --- | --- | --- | --- | --- |
| داشبورد | skeleton کارت و نمودار | چک‌لیست شروع، نه نمودار خالی بی‌توضیح | شبکه‌قطعی: تلاش دوباره. ۵۰۰: شناسه‌ی خطا | ذخیره یا اتصال موفق با toast | نقش Viewer نمودار را می‌بیند و اقدام ساخت ندارد |
| لیست اتوماسیون | skeleton جدول یا کارت | «هنوز اتوماسیونی نساخته‌اید» با CTA ساخت. فیلتر خالی: «با این فیلتر نتیجه‌ای نیست» | ۴۰۴ لیست نیست. rate limit: «چند لحظه بعد دوباره» | «اتوماسیون ذخیره شد» | Viewer دکمه ساخت را غیرفعال با توضیح می‌بیند |
| ویزارد | skeleton فرم مرحله | مرحله‌ی خالی خودش empty صفحه نیست. اعتبارسنجی inline است | توکن منقضی: بنر اتصال. شبکه: تلاش دوباره | «اتوماسیون فعال شد» | ذخیره برای Viewer بسته است |
| Inbox | skeleton لیست و حباب | «هنوز گفتگویی نیست» | webhook یا شبکه. توکن منقضی composer را هم می‌بندد | «پاسخ ارسال شد» | Agent می‌تواند ببیند. Viewer فقط خواندن، composer غیرفعال |
| مخاطبین | skeleton کارت | «مخاطبی ثبت نشده» و اگر فرم لید هست CTA به اتوماسیون | خروجی ناموفق با شناسه‌ی خطا | «خروجی آماده شد» | خروجی فقط برای Owner و Admin |
| تنظیمات | skeleton فیلدها | بخش بدون داده توضیح دارد، نه صفحه‌ی سفید | ۴۰۳ و ۵۰۰ جدا | «تغییرها ذخیره شد» | بخش نقش‌ها برای غیر Owner بسته است |
| اشتراک | skeleton کارت پلن | اگر پلنی نیست، توضیح انتظار، نه عدد ساختگی | پرداخت ناموفق: چه شد و تلاش دوباره | «پرداخت ثبت شد» | فقط Owner پرداخت می‌کند |
| اتصال اینستاگرام | skeleton کارت سلامت | «هنوز پیجی وصل نشده» با CTA اتصال | OAuth ناموفق یا حساب شخصی | «پیج وصل شد» | فقط Owner و Admin وصل می‌کنند |
| ورود و OTP | حالت loading روی دکمه | فرم خالی، empty جدا ندارد | کد اشتباه، قفل موقت، شبکه‌قطعی | ورود و رفتن به داشبورد | حساب غیرفعال با توضیح، نه حلقه‌ی خاموش |

## 12. دسترس‌پذیری

WCAG 2.2 AA حداقل است.

- کنتراست طبق جدول بخش ۳. جفت `❌` تا اصلاح توکن، برای متن عادی کوچک استفاده نمی‌شود.
- `focus-visible` همیشه دیده می‌شود. حلقه‌ی ۳px با `--ring`.
- هدف لمسی حداقل ۴۴×۴۴px در موبایل و ۲۴×۲۴px در دسکتاپ.
- همه‌ی کارها با کیبورد انجام می‌شوند. ترتیب tab منطقی و RTL است.
- landmarkها: `header`، `nav`، `main`، `aside`. لینک «پرش به محتوا» وجود دارد.
- `aria-live` برای toast و نتیجه‌ی ذخیره.
- هر فیلد label واقعی دارد. placeholder جایگزین label نیست.
- خطا با `aria-describedby` به فیلد وصل است.
- رنگ تنها حامل معنا نیست.
- zoom تا ۲۰۰٪ layout را نمی‌شکند.
- تست axe در Playwright برای هر صفحه‌ی جدید الزامی است و نباید خطای serious یا critical بماند.

## 14. چک‌لیست کیفیت UI

زیبایی و کیفیت premium الزام پذیرش است. هر صفحه یا کامپوننت وقتی تمام است که این بندها برقرار باشند:

1. فقط توکن‌ها استفاده شده‌اند. هیچ hex، px دلخواه یا سایه‌ی دلخواه در کد کامپوننت نیست.
2. هر پنج حالت loading، empty، error، success و no-permission پیاده و دیده شده‌اند.
3. RTL با logical properties رعایت شده است.
4. اعداد فارسی و تاریخ شمسی‌اند، با استثناهای بخش ۴.
5. تم روشن و تیره هر دو بررسی شده‌اند.
6. در ۳۶۰px اسکرول افقی نیست.
7. کیبورد و focus درست کار می‌کنند.
8. axe بدون خطای serious یا critical است.
9. هیچ دکمه‌ی بی‌عملکرد یا داده‌ی ساختگی در production نیست.
10. متن‌ها با بخش ۱۱ سازگارند.
11. loading بیشتر از ۳۰۰ms با skeleton نمایش داده می‌شود.
12. بعد از هر mutation بازخورد toast یا inline داده می‌شود.
13. عملیات مخرب confirm دارد.
14. تصاویر `alt` دارند.
15. محدودیت‌های Meta در جای تصمیم کاربر نمایش داده شده‌اند.
16. layout shift قابل‌مشاهده نیست.
17. اسکرین‌شات قبل و بعد در گزارش تسک آمده است.
18. هدف لمسی موبایل حداقل ۴۴px است.
19. `prefers-reduced-motion` رعایت شده است.
20. عدد جدول tabular است.
21. ماژنتا و گرادیان اینستاگرام در صفحه نیست.
22. landmark و لینک پرش به محتوا وجود دارند.
23. جفت‌های جدول کنتراست بخش ۳ حد خود را پاس می‌کنند و متن بدنه از جفت ردشده استفاده نمی‌کند، چون جفت ردشده‌ای در آن جدول نیست.
24. فونت از CDN نیامده است.
